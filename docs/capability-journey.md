# 能力路线：不是章节，而是一条生命闭环

下面每一段都以前一段为前提。它们不是“完成一个玩具”，而是在排除一种更廉价的解释。

```mermaid
flowchart LR
  A[我能重复同一个世界] --> B[我会因资源耗尽而死亡]
  B --> C[我的行动改变能量和位置]
  C --> D[我只能基于局部观察行动]
  D --> E[过去的结果在反馈缺失时仍影响行动]
  E --> F[有利控制倾向跨代保留]
  F --> G[紧凑发育规则表达结构]
  G --> H[多个线索支持未见时刻的预测]
```

## 1. 世界必须先可靠

**我要排除的解释**：行为不同只是因为随机数、GUI 刷新或隐藏全局变量不同。

`stage00_kernel` 证明离散 tick、边界和随机源是确定的。它不涉及生命，也不涉及学习。

## 2. “活着”必须有真实含义

**我要排除的解释**：系统只是走了几步，但其行为没有代价。

`life/world.py` 和 `life/organism.py` 让能量下降、食物消失、危险扣能量、死亡停止更新。这里的关键不是复杂，而是把“行动好不好”变成未来可行动时间的差异。

## 3. 不能偷看答案

**我要排除的解释**：策略只是直接读取食物或危险的绝对坐标。

`GridWorld.observe()` 只生成局部相对坐标。控制器接受 `Observation`，不接受 `GridWorld`。这让不确定性第一次进入系统：看不到时必须探索、保守或记忆。

## 4. 行为必须被单独理解

**我要排除的解释**：一个混合任务里的“成功”其实来自某个未被发现的捷径。

我们先单独研究摄食、局部趋向、局部避险；不把平衡、追逐、群体通信和识别混在一个分数里。当前最小控制器只是基线，作用是告诉我环境接口是否正确，而不是声称它聪明。

## 5. 学习不是“尝一口再知道”

**我要排除的解释**：所谓识别只是动作后读取甜/苦反馈。

`ReflexMemory` 在训练期观察“模式—动作—后果”；预测期 `predict(pattern)` 没有后果参数。这个接口约束是后续条件反射实验的底线。

真正的难点是**时间信用分配**：奖励可能在多步之后到达，错误可能被探索、噪声和其他动作掩盖。最小实现只验证隔离；不能证明已解决信用分配。

## 6. 遗传不是把答案复制一遍

**我要排除的解释**：每一代重新随机猜中一个好策略。

`life/evolution.py` 先用透明的参数进化机制验证选择、突变、边界和确定性。下一步才把适应度换成真实生命周期表现，并引入多样性保护、交叉、环境课程和 30 seed 对照。

难点是局部最优：个体可能学会“永远不动”来规避危险，也可能因为奖励设计而“永远咬”。这不是 bug，而是任务定义暴露出来的科学问题。

## 7. 发育不是画图

**我要排除的解释**：复杂结构必须把每个节点和连接直接写进基因。

`life/development.py` 从小型分叉基因确定性生成空间区间。它只证明“紧凑规则可以表达层次结构”。下一步要让这类结构真正决定传感器、控制器和连接的布局，并比较它是否优于同预算的直接编码。

难点是可修复性：一条上层分支被删掉后，结构是否还能通过变异重新出现？这也是原项目树分裂设想最值得严肃检验的地方。

## 8. 预测才是条件反射的最低门槛

**我要排除的解释**：系统只是记住固定输入表，或在测试时偷看反馈。

单像素与双像素模块是接口基线：训练和测试数据流已经分离，双像素输出混淆矩阵。但它们当前仍是透明统计/查表基线，不是模式泛化。

下一步真正的实验应加入未见位置、时序延迟、噪声和干扰模式，并要求系统在没有反馈时仍有更高预期收益。只有这一步成立，“感知在预测后果”才有初步证据。

## 9. 结构、记忆与生存最终要在同一世界相遇

目前这些能力已分别有最小实现。下一轮不该再添加更多孤立小模块，而应将它们组合成一个完整实验：

```text
发育基因 → 传感/连接布局 → 个体控制器
       ↓                     ↓
跨代选择 ← 生命周期得分 ← 局部世界中的感知—行动—后果
                              ↓
                         生命周期内的记忆更新
```

这个整合实验才是 Frog 的核心工程挑战。
