# 03：实验可复现性契约

本文件是 `lab/` 所有实验的最低规则。它的目标不是让项目变慢，而是避免把偶然动画误当成能力。

## 每次运行必须记录

每个实验运行目录必须保存：

```text
runs/<experiment-id>/<timestamp>-seed-<n>/
  config.json          # 完整参数快照
  metadata.json        # git SHA、JDK、OS、启动命令、seed、时间
  metrics.json         # 汇总指标
  telemetry.csv        # 每 step / 每 episode 的原始数据
  events.jsonl         # 动作、奖励、死亡、繁殖、突变等事件
  optional-frame/      # 可视化截图，仅作解释用
```

随机数必须从一个明确的根 seed 派生；禁止在逻辑中散落 `new Random()` 或 `Math.random()` 而不记录来源。

## 训练、验证、测试不可混用

| 集合 | 允许做什么 | 禁止做什么 |
|---|---|---|
| Train | 接收奖励/惩罚、更新权重、产生下一代 | 用作最终结论 |
| Validation | 选择超参数、检查退化 | 更新个体、选择最终样例 |
| Test | 仅一次或预先锁定的评估 | 反复调参直到好看 |

对条件反射任务，**测试阶段不得提供甜/苦标签作为决策输入**。否则智能体可以“先咬再知道”，绕开视觉预测目标。

## 最低统计要求

任何“学会了”“更好”的结论须满足：

- 至少 **30 个独立随机 seed**；
- 报告均值、标准差、成功率、95% 区间或等价统计；
- 同时报出失败种子、平均步数、奖励、错误动作数；
- 对比至少一个 baseline：随机策略、固定规则、或固定拓扑学习器；
- 保留原始 CSV/JSON，不只保留汇总图。

建议核心指标：

```text
准确率、毒物误食率、甜食漏食率、空咬率、累计能量、存活率、
首次学会所需 episode、泛化准确率、计算预算（episode/评估次数）
```

## 防奖励投机规则

出现以下任何情况，都必须标为“任务定义被绕过”，不能报作成功：

1. 永远执行咬/逃/静止中的一个动作，恰好在当前奖励设定下得分高；
2. 测试时读取了训练期才应可见的反馈；
3. 用位置、时间或 UI 刷新顺序代替视觉模式；
4. 训练和测试使用同一组固定图案；
5. 只挑一个漂亮 seed 展示；
6. 通过硬编码目标映射而没有在设计中声明。

## 可视化的地位

GIF、图表、神经网络连线图用于解释“发生了什么”，不用于证明“能力存在”。每一个画面必须能关联到运行目录的 seed、配置和指标。

## 结论模板

```text
在任务 X、预算 Y、30 个独立 seed、隐藏测试集 Z 下，方法 A 的成功率为 …；
相对 baseline B 的差异为 …。因此仅可得出：……。
尚不能得出：……。
```

这也是项目讨论“复杂智能”时最重要的安全护栏。
