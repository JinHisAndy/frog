# Frog 学习重建规则

## 1. 不破坏历史

- `history/`、根目录历史 GIF/PNG/JPG、`record/`、`other/`、原始 README 是**不可修改的参考档案**。
- 不在历史版本上继续叠加功能；若要修复其运行问题，单独记录补丁和原因，不覆盖原文件。
- 新实现只进入 `lab/`；先保持功能等价，再谈改进。

## 2. 一次只验证一个假设

每个实验必须有一份 `lab/experiments/.../README.md`，至少写清：

1. 问题和唯一主假设；
2. 输入、动作、奖励和终止条件；
3. 训练/验证/测试如何隔离；
4. 对照组；
5. 指标、成功阈值、失败/停止条件；
6. 固定随机种子和配置文件位置。

“能跑出一张图”不等于实验成功。

## 3. 先测试、后可视化

实现顺序固定为：

```text
JUnit 单元测试 → 无界面 CLI/批量实验 → CSV/JSON 指标 → Swing 可视化
```

UI 只展示已由无界面实验验证过的状态，不能承担判定正确性的职责。

## 4. 不夸大结论

- 不将随机搜索到一个符合样例的网络称为“进化出了智能”。
- 不因使用了“多巴胺、杏仁核、LTP”等名称就声称进行了生物脑仿真。
- 不因一个 GIF 或单个 seed 成功就声称具有学习能力或泛化能力。
- 不把“自我意识”作为可接受的工程验收描述；只能报告可量化行为。

## 5. 小提交与可回滚

建议分支：`lab/stage-00-kernel`、`lab/stage-01-energy` 等。每个提交只包含一个可运行的小变化，提交信息采用：

```text
feat(stage-02): add seeded mutation operator
 test(stage-02): cover mutation bounds
 docs(stage-02): record 30-seed result
```

提交前运行相关测试、`git diff --check`，并保存实验配置和结果索引。
